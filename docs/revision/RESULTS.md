# 整改操作与测试

## 操作顺序

1. 在首页搜索“综合楼”并点击地点。打开 **地图校准** 可切换 GIS 锚点叠加，关闭后回到三维地图。**渲染指标** 实时显示抽样帧率与场景绘制规模。
2. 打开 **行程优化**，设定北门、南湖运动场、综合楼、南湖体育馆、南湖食堂。保留北门和食堂为首尾。勾选 **自动优化中间站顺序** 后点击 **生成行程**，查看原顺序、采用顺序与算法实测结果。取消勾选可按原顺序重算。
3. 登录后保存多站行程，在 **个人空间 → 多站行程 → 打开行程** 恢复输入。再次生成时使用当前发布版道路图。
4. 在 **地图纠错** 选择道路，提交对“综合楼西广场 → 中央步道”的反馈。管理员在 **反馈处理** 写回复，再点 **打开对应对象并关联发布**。
5. 取消该段 **开放通行**，点 **保存草稿**，刷新后台可恢复。当前公开地图在这一步保持原修订。填发布说明并点 **发布地图**，将当前草稿、发布版本和关联反馈写入数据库。
6. 普通用户打开 **路径规划**，从北门到食堂重新计算。算法对比卡显示新修订，地图路线绕开关闭的路段。到 **管理后台 → 地图版本** 恢复先前版本，会产生一个新修订，路线再次使用恢复后的路段。

## 核心实现

- **同图双算法**使用同一份发布快照、入口、边权和台阶约束。Dijkstra 的优先队列用累计边权，A* 加上节点至终点的欧氏下界。每段分别计时并统计从队列展开的节点，合计后展示。路线的渲染及网络耗时不参与统计。两个算法找到的路线可能在等长支路上不同。
- **行程优化**先用道路最短路径建立所选入口的对称距离矩阵。起终点固定，中间站最多 10 个时用 Held–Karp 子集动态规划，复杂度为 O(k² · 2ᵏ)。11–12 个中间站用最近邻构造初解，再做 2-opt 调整，初解较差时从原顺序开始改进。启发式有改善但不承诺全局最优。
- **持久化**沿用项目的 Spring Security、Spring JDBC 和个人记录隔离。新表 `scene_drafts` 记录账号、草稿令牌和基础修订，`scene_revisions` 保存历史场景、作者、说明和来源版本。临时关闭、入口、建筑几何、校准比例在同一快照。发布原子更新当前快照与历史，并可关联用户反馈。历史恢复使用相同发布校验并递增版本。
- **发布校验**检查 ID、已有业务引用、尺寸、位置、出入口接入、线段穿楼或跨水，以及校准地图中道路相交缺少公共路口的情况。历史数据引用不兼容时拒绝恢复。原版地图具有可调用的历史记录，三维画法由当前程序统一生成。
- **兼容旧库**首次启用版本功能时存档原有快照。已有场景完全匹配旧版发布模板时自动发布校准版。管理员自行改过的场景会保留，且可通过 JSON 草稿验证后发布。账号、私有行程、收藏、路线、导览和反馈使用原表和原主键。

## 实测结果

环境为 Windows，Java 21.0.8，Maven 3.9.11，Chrome 156.0.8078.81，桌面截图 1440 × 880。两个画面均用无头 Chrome 的 SwiftShader 渲染。最终 Vue/JavaScript 页面由 Vite 构建，后端使用 Spring Boot 3.5.7。

| 用例 | 结果 |
| --- | --- |
| 北门 → 食堂，同一通行条件 | 两算法均为估算 399.9 m。H2 一次实测 Dijkstra 展开 15 个节点、3.268 ms，A* 展开 6 个节点、0.074 ms。单次计时受首次调用、JVM 和机器调度影响。 |
| 避台阶与发布关闭 | 本样例均将中央路段排除，替代路线估算 462.3 m。恢复历史场景后返回原路；隔断北门给出 422。 |
| 起终点一致、多途经点 | 同入口返回单点零距离。逐段核对途经顺序、入口和路网边编号。 |
| 五站精确样例 | 估算距离从 1,962.3 m 降到 1,484.7 m，固定首尾并枚举全部 6 种中间顺序，核对结果与最短值一致。 |
| 14 站启发式样例 | 从估算 3,651.0 m 降到 2,114.1 m。本样例用于验证路线改善和算法切换。 |
| 浏览器业务闭环 | 已验证搜索选中、生成保存并刷新恢复多站行程、反馈回复、从反馈打开道路、草稿刷新恢复、发布、用户重算、历史恢复和重新规划。无未处理浏览器异常或意外接口失败。 |
| 权限与地图保护 | 游客读取管理历史返回 401，普通用户恢复版本返回 403，其他账号不共享验收行程。无效端点或未接通的交叉道路发布返回 400，公开地图修订保持一致。 |
| 旧库和重启 | 用有既存登录与图书馆收藏的旧 H2 数据库副本验证迁移。升级后已有账号可登录，收藏仍在。另在整改版重启后复核了多站行程、反馈关联、发布历史和未发布草稿。 |
| MySQL | MySQL 8.4.13 实际建表并通过算法和权限用例。另用接口验证了保存草稿、反馈引用缺失时发布事务回滚、成功发布和版本恢复。浏览器发布闭环使用 H2。 |
| 视觉与操作 | 实测北门与食堂的镜头切换、食堂楼体碰撞和反向移动、选中状态和北向对照。 |
| 性能 | 基线 2,621 ms 渲染 65 帧、16,510 次 WebGL 绘制，约 24.8 FPS、254 次/帧。整改版 2,622 ms 渲染 72 帧、12,024 次 WebGL 绘制，约 27.5 FPS、167 次/帧。应用统计样本为 25,432 三角面、20 个几何和 1 张纹理。此数据只对应本次静止俯瞰采样。 |
