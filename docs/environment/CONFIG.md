# 校园环境与 Agent 使用说明

## 校园环境

点击地图上方时间，或左侧 **校园环境**。后端提供 UTC 基准，页面以 Asia/Shanghai 推进北京日历，并定期和前台恢复时校时。校园采用 WGS84 近似点 **30.51079° N，114.35391° E**，基于南湖综合楼公开地理点。Open‑Meteo 返回区域模式网格，气象有效时间与应用拉取时间分别显示。正式默认使用现实模式。[南湖综合楼 WGS84 参考](https://mapcarta.com/W779843668) · [Open‑Meteo API](https://open-meteo.com/en/docs)

太阳由锁定版本 SunCalc 1.9.0 计算。该版本太阳方位角从南向西为正，运行程序加 π 取模转换为从北顺时针的方位。世界坐标 X 向东、Z 向南、Y 向上，光向量为 `(sin(A)cos(h), sin(h), -cos(A)cos(h))`。太阳高度连续控制日夜色彩、主光和夜灯。主光跨过小角度门槛时更新阴影图。夜灯、窗灯和少量光照均为虚拟规则。[SunCalc 1.9.0 实现](https://github.com/mourner/suncalc/tree/v1.9.0)

Open‑Meteo 免费接口适用于非商业演示，默认成功缓存 15 分钟，失败后等待两分钟重试。出现超时、限流或无数据时，已有采样保留且过期会标注。未提供的字段显示为未知。能见度取同一有效时段附近的小时数据。打开 **昼夜与天气测试** 可用固定北京时刻和晴、阴、雨、雪或缺失字段复拍，界面会显示测试标记。此开关仅控制本机显示，不更改真实时钟、气象或 Agent 预报。[Open‑Meteo 使用条款与署名](https://open-meteo.com/en/terms)

`NANHU_WEATHER_ENDPOINT` 默认 `https://api.open-meteo.com/v1/forecast`。 `NANHU_WEATHER_FRESH` 和 `NANHU_WEATHER_RETRY` 支持 ISO 8601 时长格式，用于独立测试实例缩短缓存窗口。指向回环地址的气象数据会明确标为测试源。

## 自然语言配置

后端使用 OpenAI 兼容 Chat Completions 和函数工具。服务必须支持 `POST /chat/completions`、`tool_calls` 和带 `tool_call_id` 的工具回传。HTTPS 用于远程服务，回环地址允许 HTTP。以下变量只从启动进程读取。

| 环境变量 | 值 |
| --- | --- |
| `NANHU_AGENT_BASE_URL` | 服务基址，包含服务规定的 API 前缀，通常以 `/v1` 结尾 |
| `NANHU_AGENT_MODEL` | 提供方精确模型名 |
| `NANHU_AGENT_API_KEY` | 提供方 Bearer 凭证，由本机进程环境或安全的秘密注入方式提供 |

配置后用同一环境停止并启动项目。在 **校园 Agent → 自然语言** 发送测试。凭证由 Java 后端设置请求头，页面和工具执行日志不包含凭证。默认未配置会提示缺少服务，**时间行程表单** 继续使用真实算法、天气和数据库。

## 示例及动作

- “定位南湖综合楼。” 会搜索真实地点并请求定位。
- “只显示食堂。” 会请求餐饮图层。
- “查看这个建筑的信息”“收藏这里”需要当前选中的地点，收藏需登录。
- “从当前选中的建筑到综合楼”“播放刚才规划的路线”“停止播放，回到全校视角”使用真实地图状态与路线。
- “明天 12:45 从北门出发，食堂停十分钟，14:00 前到综合楼，尽量少走露天路段。” 会获取校园时间，查找服务和开放时间，获取预报，计算道路路线，并绘制行程。校园没有已核实打印点时会如实提示。
- 明确要求保存的自然语言请求会打开保存确认按钮。执行保存后可在 **个人空间 → 多站行程** 打开结构化结果。

地点、图层与动作均校验。单次对话最多五轮、十次工具调用，超时返回明确错误。时间行程固定首尾，枚举最多六个中间站，根据路网、开放窗口、等待、停留和截止时间选最早可行顺序。结果显示各段路线、天气和未核实项。开放时间、道路遮蔽属性由管理员维护。初始地图的开放时间和遮蔽资料尚不齐全，系统如实标为未知。时间约束行程使用单个北京日内的开始和截止时间，支持未来 60 天内计划，天气只在供应商有覆盖时提供。
