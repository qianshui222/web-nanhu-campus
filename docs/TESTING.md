# 实际测试记录

本页为初版运行记录。最终整改版功能、性能与迁移复验见 [整改操作与测试](revision/RESULTS.md)。

测试日期为 2026 年 11 月 23 日。环境为 Windows、Java 21.0.8、Maven 3.9.11、Node.js 24.22.1、Vite 7.1.7、Spring Boot 3.5.7。浏览器为 Chrome 156.0.8078.81，通过 Playwright 1.56.1 操作。浏览器流程使用 1440×880 桌面及 390×844 移动尺寸。H2 文件配置和临时 MySQL Community 8.4.13 数据库使用相同的建表 SQL、校园种子和业务接口。

| 检查 | 实际结果 |
| --- | --- |
| 构建 | Vite 构建成功，Maven 清理重建成功，全部七个 Java 文件以 Java 21 编译。Spring Boot 产物中包含应用和依赖。 |
| 启动 | 用 Windows `start.bat` 实际加载本地地图和 API。Vite 开发服务器在 5173 返回页面、Vue 模块和代理后的校园 API。通过停止脚本确认项目进程退出，再以原数据库重启。 |
| 底图和交互 | 浏览器渲染 14 个地点、42 条路段和岸线，截图复核桌面构图、综合楼立面、路线、个人空间、后台和移动端。浏览器操作了旋转、缩放、复位、图层、小地图渲染、标签悬停和地点详情联动。综合楼照片加载成功。 |
| 第一人称 | 模拟按键验证综合楼入口附近的运动受楼体边界阻挡，反向步行离开楼体时坐标变化。验证进入、退出及相机复位。 |
| 路径 | H2 和 MySQL 均验证单点零距离、普通通达、双途经点的既定顺序、避台阶、关闭道路后绕行及断路时 422。逐段比对返回的节点、边和估算长度。浏览器验证开始、暂停、继续和重新开始。 |
| 账户和隔离 | 注册、登录、注销通过。普通账号调管理接口返回 403，游客调私人接口返回 401，缺少 CSRF 的写请求返回 403。独立账号列表只含自身记录，按另一个账号的行程或路线编号提交编辑和删除均返回 404。 |
| 个人记录 | 浏览器验证收藏、路线、行程刷新仍可读，尝试保存重叠行程出现明确提示。接口验证个人记录编辑、删除和注销后重登仍存在。 |
| 导览与反馈 | 浏览器验证站点完成和页面刷新恢复，服务端拒绝跳站。验证从普通用户提交到管理员回复，再切回普通用户查看处理结果。接口覆盖待处理、处理中、已处理三种状态。 |
| 编辑、导入与恢复 | 浏览器更改综合楼名称、高度和颜色，核对地图标签、地点详情及刷新后持久化，再通过导出文件恢复场景。接口验证过期修订、无效端点及与道路冲突的楼体设置被拒绝，比较失败前后的快照与修订号一致。 |
| 持久化重启 | H2 与 MySQL 的 Spring Boot 实例实际停止并重新启动。用重启前创建的账号再次登录并查询到图书馆收藏。 |
| 浏览器控制台 | 关键流程无未处理 JS 异常、无意外 HTTP 失败。冲突用例出现预期的 HTTP 409，表单已显示冲突原因。 |

桌面概览静置，Chrome 无头模式使用 SwiftShader 软件渲染，`requestAnimationFrame` 在 2,113 ms 内记录到 60 次回调，约 28 次/秒。这个数值用于记录本次浏览器环境，真实设备的 GPU、浏览器和屏幕尺寸会影响结果。Vite 报告了约 684 kB 的生产主脚本体积提示，当前交付使用这一生产构建。

本次移动端检查采用浏览器模拟尺寸。坐标、距离、出入口几何和台阶属性需要实地复核。现场 GPS、实际无障碍条件、代表性客流和多实例部署未纳入验收。可复跑的 Playwright 脚本位于 `verification`，建议使用独立演示数据库执行。
